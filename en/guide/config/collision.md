# `collision.yml` —— 真实碰撞箱与交互

管的是「**玩家能不能撞到、能不能打到物理化的方块**」。

与 [`view.yml`](view.md) 是两回事：那边管「看到什么」，关掉只是变难看；
**关掉这里的项会改变玩法** —— 碎块从能挡人变回可以直接走过去。

---

## 为什么它必须逐玩家发包、还要带预算

碎块的视觉走的是**骑乘组**：一个隐形根实体带着 N 个 block display 当乘客，平移整簇只要一个包。

但骑乘组**给不了碰撞箱** —— 客户端把每个乘客的实体位置都摆在载具的挂点上，
`Transformation` 只是渲染偏移、不参与碰撞。一个 64 方块的簇在客户端只有**一个点**有实体位置。

所以「方块真的挡住人」只有一条路：**给每个方块一个独立定位的实体**，各自收位置包。
带宽从 O(簇数) 退回 O(方块数) —— 这就是下面每一个数字存在的理由。

!!! tip "好在它只在玩家身边才有意义"
    人只可能撞到自己够得着的东西，而原版对实体的判定距离只有 3 格（创造 5 格）。
    十几格外的碎块有没有碰撞箱，玩家永远不会知道。

## 总开关与模式

```yaml
enabled: true
mode: SHULKER
```

关掉之后碎块退回纯视觉（可以直接穿过去），带宽回到骑乘组的量级。

| `mode` | 挡人 | 可打 | 适用 |
|---|---|---|---|
| `SHULKER` | ✔ | ✔ | **默认**。一种实体同时满足碰撞与交互两个需求，最省带宽 |
| `INTERACTION` | ✘ | ✔ | 「要能打、不要挡路」的服务器 —— 隐形实心方块在跑酷图里把路封死是灾难 |
| `NONE` | ✘ | ✘ | 等价于 `enabled: false`，但保留交互配置便于临时切换 |

!!! note "潜影贝这条路已在 26.2 的 Mojang 源码上复核过"
    `Shulker.canBeCollidedWith` 仍然覆写为 `return isAlive()`，而客户端的血量默认值就是 1.0 ——
    所以只发「生成 + 隐形」两个包就能挡人。

## 两档激活半径

```yaml
radius: 8.0
moving-radius: 8.0
```

| 键 | 默认 | 说明 |
|---|---|---|
| `radius` | 8.0 | **已停稳**碎块的激活半径（格） |
| `moving-radius` | 8.0 | **运动中**碎块的激活半径。`0` = 飞行途中完全不给碰撞箱 |

8 格意味着「下一秒内可能撞到的东西都已经有碰撞箱了」
（玩家交互距离 3~5 格 + 跑动一 tick 位移 < 0.5 格）。

!!! danger "26.2 的潜影贝没有客户端插值"
    `getInterpolation()` 返回 `null` —— 它收到位置包是**硬瞬移**（这一点与 Display 完全不同）。

    后果很具体：正在下落的碎块，碰撞箱每次广播阶跃一次，
    站在上面的玩家会被反复「顶起—掉落」。

    而**已经停稳的废墟堆没有这个问题** —— 它根本不再发位置包。

所以两者分开配。真机测下来若飞行中的碰撞手感糟糕，把 `moving-radius` 调成 `0`：
那样只有落定的废墟能站上去，飞行中的碎块仍然可以打、但不挡路。

`moving-radius` 与 `radius` 取齐（8）而不是更小的 5：
5 格意味着一块正朝你飞来的碎块要等到已经贴到脸上才获得碰撞箱，而它下一帧就飞过去了。

## 预算

```yaml
budget-per-viewer: 96
max-viewers: 8
```

| 键 | 默认 | 说明 |
|---|---|---|
| `budget-per-viewer` | 96 | 每玩家同时存在的碰撞箱实体上限，超出的按距离由远及近舍弃 |
| `max-viewers` | 8 | 单场坍塌最多给几名玩家发碰撞箱 |

**带宽账**：一个绝对位置包是 66 字节，96 个盒在 10 Hz 下峰值约 **63 KB/s/人**。

!!! note "这是最坏情况"
    只在「一大团碎块正贴着你飞」的那几秒出现。
    稳态接近 0 —— 玩家真正会踩上去的废墟全是停稳的簇，它们只补一帧终态就停发。

`max-viewers` 比 [`budget.yml`](budget.md) 的观众名额小一档：
一场倒塌被 30 人围观时，真正会走进废墟堆的永远只是最近的那几个。

## 攻击与右键

```yaml
interact:
  enabled: true
  attack-speed: 4.0
  use-speed: 1.2
  sneak-multiplier: 2.0
```

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 关掉之后碰撞箱仍然挡人，只是打不动 |
| `attack-speed` | 4.0 | 一次攻击给**单个方块**带来的速度增量（m/s） |
| `use-speed` | 1.2 | 一次右键的速度增量。通常远小于攻击，只是「推一把」 |
| `sneak-multiplier` | 2.0 | 潜行时的倍率。潜行左键 = 蓄力砸 |

### 为什么配速度而不是冲量

**速度是唯一能凭直觉判断的量。**

配冲量的话，服主得先知道「一格石头有多重」（2500 kg）才填得出合理值。

而按**单块**质量折算之后，打一整面 64 格的墙只能获得 `4/64 ≈ 0.06 m/s` ——
这正是应该的（墙比一块砖重 64 倍），且不需要任何特判，是 `Δv = J/m` 自己给出来的。

## 已知短板

真机验证前请先读完这一段。

### 客户端会把隐形潜影贝对齐到方块网格

`Shulker.setPos` 里有一句 `Mth.floor`。

- 对已经停稳、格点对齐的废墟堆 —— 碰撞盒**完全精确**
- 对飞行中带小数坐标的碎块 —— 是「最近那一格」的近似，最大误差半格

好处是它顺带消除了抖动（格点是稳定的，盒不会随亚格级位姿来回跳）。
代价是**盒永远轴对齐**：一块斜着飞的方块，碰撞盒不会跟着倾斜。

服务端按同一条公式先吸附一次，所以攻击判定与你看到的盒是一致的。

!!! important "因为这一条，常驻物体按外形分两档"
    - 接近一格立方的（物理 TNT、方块型小物件）→ 与碎块同样用潜影贝、**真的挡人**
    - 车与布娃娃这类异形 → 退回 `INTERACTION`，盒逐个贴合外形但不挡人

    拿 1×1×1 去挡一辆 3×1.5 的车，得到的是「明明走得过去却被卡住」与
    「明明该挡住却穿过去」的混合体，比不挡更糟。

### 其余四条

| # | 短板 |
|---|---|
| 1 | 碰撞箱没有客户端插值（见上面 `moving-radius` 的说明） |
| 2 | 隐形潜影贝只会「软推」玩家：原版的实体互推只有**水平分量**，所以「碎块把人横向挤开」是免费的，「人站在移动的碎块上被带着走」不是 |
| 3 | 服务端并不知道这些碰撞箱存在。玩家站在半空中的碎块上时，服务端的飞行检测可能在约 80 tick 后把他拉回地面 —— 长时间站立才会出现，坍塌那几秒不会 |
| 4 | 攻击判定用的是服务端算出来的盒位置，客户端看到的是上一次广播的位置。快速下落的碎块上两者会差 0.5~1 格 —— 碰撞箱只在近距离激活正是为了压住这个误差 |

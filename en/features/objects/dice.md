# 骰子

六个骰子模板。参数标定过，用 `SpawnOptions` 照着填能复现同样手感。

!!! info "生成入口的现状"
    见[物体模板总览](index.md)顶部的说明 —— 引擎已没有内置的 `/gtrp spawn`。

---

## 参数表

质量统一 **17**。

| id | 名称 | 半边长 | 外观方块 | 碰撞形状 |
|---|---|---|---|---|
| `dice_4` | 四面骰子 | 0.45 | `DIAMOND_BLOCK` | 四面体**凸包** |
| `dice_6` | 六面骰子 | 0.25 | `GOLD_BLOCK` | 盒 |
| `dice_6_s` | 实心六面骰子 | 0.25 | `IRON_BLOCK` | 盒 |
| `dice_8` | 八面骰子 | 0.30 | `EMERALD_BLOCK` | 八面体**凸包** |
| `dice_10` | 十面骰子 | 0.50 | `LAPIS_BLOCK` | 十面体**凸包** |
| `dice_12` | 十二面骰子 | 0.24 | `AMETHYST_BLOCK` | 十二面体**凸包** |

## 为什么非立方体骰子要用真凸包

用正方体近似所有骰子最省事，但会丢掉骰子最要紧的那件事：

!!! important "骰子的意义是「按面停在桌上」"
    正方体近似**永远只会停在面上**。

    真多面体能停在**面 / 棱 / 顶点** —— 四面体立在一个角上摇晃两下再倒，
    十二面体滚很久才停，这些才是骰子该有的样子。

所以 `dice_6` / `dice_6_s` 走盒路径（它们本来就是正方体），其余四个走凸包。

### 凸包的已知限制

作为**运动的一方**精确（顶点即采样点），作为**被压的一方**退化成包围盒。

骰子是被扔来扔去的小物件，很少充当承重面，所以这个退化在这里无所谓。
完整说明见[性能与上限](../../engine/limits.md#凸包是半精确)。

## 掷出的初速

生成时不是「原地放下」，而是**掷出去**：

```java
vx = 高斯随机 × 1.5          // 水平散布
vy = 1.0 + 随机 × 1.5        // 上抛
vz = 高斯随机 × 1.5

角速度 = 三轴各 高斯随机 × 3.5   // 随机自旋
```

!!! tip "随机自旋不是装饰"
    没有它，骰子会「啪」一下拍平落地。
    有了它才会在落地时自然翻滚几下 —— 这是「掷骰子」与「放骰子」的区别。

---

## 惯量

不需要手填。引擎的 `MassProperties` 从盒 / 凸包顶点解析地算出完整 3×3 惯性张量，
包括非对角的惯性积。

不同尺寸的骰子因此有正确的**非均匀**惯量 —— 一个扁的十面骰子绕三个轴的转动惯量是不一样的。

详见[质量与惯性张量](../../engine/mass.md)。

## 用 API 复现

```java
PhysicsBody die = api.bodies().spawn(
        SpawnOptions.builder(loc, Material.GOLD_BLOCK)
                .halfExtents(0.25)
                .mass(17)
                .build());
if (die != null) {
    die.applyImpulse(vx * 17, vy * 17, vz * 17);   // Δv = J/m
    die.setAngularVelocity(sx, sy, sz);
    die.broadcastTo(loc.getWorld());
}
```

!!! note "`applyImpulse` 收的是冲量不是速度"
    想要 `Δv` 就乘上质量。这条对所有物体都适用。

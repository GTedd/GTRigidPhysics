# 接触生成

> 源码：`engine/ContactGenerator.java`、`engine/ContactSet.java`

窄相位负责把「刚体 vs 地形」「刚体 vs 刚体」变成一组接触约束。
每个子步都重新生成一次 —— 位置在子步之间已经变了，旧接触手里的几何立刻过期。

---

## 点云 vs 盒

窄相位比的是 **A 的表面采样点** 与 **B 的盒**，不是两个盒之间的最小平移向量。

理由是杠杆臂，已经在[碰撞形状](shape.md#为什么是盒--点云)里讲过：MTV 只给一个整体推开方向，
一块砖搭在台沿上只会被平推开；逐点接触能算出每个点到质心的力臂，砖就自然绕着台沿翻下去。

**倾覆、侧翻、角端掀起 —— 坍塌里最好看的那些，全部是杠杆臂涌现出来的，没有任何特判。**

---

## 只沿暴露面退出 —— 幽灵碰撞的根治

### 病象

碎块在**平地**上滑过时，莫名其妙被弹起、被卡住、或者被横推一把。

### 病因

地形是由一堆盒拼成的。相邻两盒之间有一条**几何上不存在、求解器却看得见的内部边**。

一个稍微陷进地面的采样点，几何上的最近退出方向可能被算成**水平**的 ——
那条方向来自两个相邻方块之间根本不存在的缝。碎块于是被那条缝横推一把。

```
       碎块采样点 ↓
    ┌──────┬──────┐
    │ 地形 │ 地形 │   ← 这条接缝在几何上不存在
    └──────┴──────┘      但它是两个盒的边界，最近退出方向可能沿它水平指出去
```

### 通用引擎怎么办

靠**启发式去猜**哪条边是内部边。Jolt 的 `EnhancedInternalEdgeRemoval` 就是这么一个开关 ——
它有效，但它是猜的，猜错的场合就是残留的幽灵碰撞。

### 这里怎么办

!!! success "体素世界根本不用猜"
    建地形时我们手上就有**占据位图**。哪个面贴着另一个实心方块，是**已知事实**而不是待推断的量。

每个盒带一个 6 位暴露掩码（`TerrainField.FACE_NEG_X` … `FACE_POS_Z`，`FACE_ALL = 0x3F`），
被相邻实心方块盖住的面对应位清零。窄相位**只允许沿暴露面退出**。

内部边在几何层面就不存在了。这比任何启发式都干净，也是自研引擎相对通用引擎最直接的一项收益。

同一套机制在 `BodyShape` 里也有一份 —— 一个多方块的簇，内部接缝同样要剔除。

## 投机接触

接触在**还差一点点碰上**时就建立（距离 < margin），约束在求解时才真正生效。

于是高速物体在这一子步内被「提前拦住」，**不必做连续碰撞扫掠，也就没有隧穿**。

margin 随速度增大，正好覆盖本子步的位移：

| 常量 | 值 | 说明 |
|---|---|---|
| `SPECULATIVE_DISTANCE` | 0.05 格 | 基础投机距离，速度带来的额外余量在此之上叠加 |
| `INSIDE_EPS` | 1e-9 | 认定「点在盒内」时向内收的容差，避免恰好共面时反复在内外之间跳 |

## 接触存的是「可重算的约束」，不是冻结的穿深

这是位置法求解器最容易翻车的地方，值得单独说清楚。

### 每条接触记录什么

- A 上的一个**局部锚点**（相对质心）
- 一个**贴在 B 上**的平面：法线 + 平面上一点（B 的局部坐标；B 是地形时退化为世界坐标）

约束值 `C` 在求解的**每一次迭代**里由当前位姿重新算：

```
C = n_world · (锚点_world − 平面点_world)
```

### 为什么不能存一个算好的穿深数字

!!! danger "经典翻车方式"
    一个刚体同时压着好几个接触时，第一条接触把它推开之后，**剩下几条手里的穿深就已经过期了**。
    照着过期的数字继续推，物体会被合力弹飞。

重算约束值从根上没有这个问题 —— 每次迭代看到的都是当前真实几何。

## 为什么用 SoA 平铺

`ContactSet` 把所有字段按**结构体数组**（Structure of Arrays）平铺，而不是每条接触一个对象。

一场坍塌单个子步可以产生**上万条接触**。对象化就是每秒几百万次分配，
GC 会直接吃掉物理线程的预算 —— 而物理线程的预算本来就是按帧算的。

### 字段清单

| 字段 | 含义 |
|---|---|
| `bodyA` / `bodyB` | 两侧刚体下标。`bodyB == -1` 表示对方是静态地形 |
| `anchor` | A 上锚点的**质心相对局部**坐标 |
| `normal` | 接触法线，指向「把 A 推开」的方向 |
| `plane` | 平面上一点，坐标系同 `normal` |
| `friction` / `restitution` | 该接触的摩擦系数与恢复系数 |
| `lambdaN` | 位置求解累计的**法向**拉格朗日乘子 |
| `lambdaT` | 位置求解累计的**切向**乘子。静摩擦的预算就是它与 `μ·lambdaN` 的差 |
| `vnPrev` | 生成这一刻的法向相对速度（负值 = 正在接近），恢复系数要用 |
| `frictionApplied` | 速度求解阶段已施加的摩擦冲量 |

### `frictionApplied` 为什么必须存在

速度求解要迭代 8 次（雅可比平均单次是欠松弛的，见 [XPBD 求解器](xpbd.md#为什么必须雅可比平均)）。

而库仑摩擦的上限 `μ·lambdaN / h` 是**整个子步**的预算，不是每次迭代的预算。

少了这个累加器，摩擦会被施加 8 遍 —— 所有东西都会像陷在沥青里。

## 广相剪枝

刚体 vs 刚体走**扫掠剪枝**（Sweep and Prune）：按某轴排序后只测区间重叠的对。
复用数组 `order` / `sweepMin` 避免每帧分配。

刚体 vs 地形不走 SAP —— 地形有自己的稠密格子索引，查询直接是 O(1)，见 [地形场](terrain.md)。

---

## 线程约束

!!! warning "`ContactGenerator` 非线程安全"
    内部有大量复用暂存数组，**一个实例只能由一条物理线程使用**。
    每个物理世界持有自己的一份。

## 撞击记录

接触生成时顺带记录「够响的撞击」，供两个上层系统消费：

- **撞击后果**（`impact.yml`）—— 脆的自碎、硬的砸坏方块
- **表现层反馈**（`view.yml` 的 `impacts` 段）—— 撞击音效与小团扬尘

通过 `impactSink(ImpactSink, minSpeed)` 注册，低于 `minSpeed` 的接触直接跳过。
物理线程侧只保留**最响**的那几次（`ClusterImpactRecorder.CAPACITY = 16`），
所以表现层把播放频率调小不会漏掉重要撞击。

    力系统🔗

    源码：engine/RigidBody.java（累加与积分）、engine/ForceGroup.java（来源分类）、 physics/ClusterPhysicsWorld.java / ObjectPhysicsWorld.java（各类力的施加点）

    物理引擎里的「力」来自不同源头，作用方式完全不同。把力分类是为了回答三个问题： 它在哪个线程生效？谁决定它的强弱？下游怎么调它？

    混为一谈的后果很具体 —— 「想调摩擦却不知道改哪里」。

    两套分类，各管一件事

    本页讲的是类型学（力从哪来、生命周期归谁）。 还有一套按来源标签的分类用于调试可观测性，见 力记账。 两者正交：同一份升力在类型学上是「主动力」，在记账上是 ForceGroup.LIFT。

    四分类🔗

    类别 特点 作用时机 引擎中的力
    A. 介质 / 材料力 由物体材质与所处介质决定，持续作用 每子步 重力、空气阻力、浮力、流体阻力、摩擦、弹性
    B. 场力 由场景中的力场决定，玩法控制 每子步（场存活期间） 引力井、磁力场
    C. 瞬时力 一次性施加，随即消失 调用瞬间 冲量、力偶矩、爆炸冲击、水面反弹
    D. 约束力 由接触 / 约束求解器产生 求解器迭代内 法向支撑、堆叠传递、库仑摩擦、铰链与滑轨

    分类依据不是力的大小，而是谁拥有它的生命周期：

    • A 的生命周期属于材质与介质 —— 物体进了水就浮、冰面上就滑，是环境自动给的
    • B 的生命周期属于力场 —— 黑洞造出来就吸，撤掉就停，是玩法主动放的
    • C 的生命周期是一瞬间 —— 冲量砸下去就没了
    • D 根本没有「力」的实体 —— 它是求解器为满足「不能穿透」算出来的位置修正

    A 类：介质 / 材料力🔗

    力 引擎实现 调参入口
    重力 a = g × gravityScale，在积分阶段直接加到速度上 physics.yml 的 gravity；运行时 /gtrp sim gravity
    空气阻力 二次阻力 a = −k·\|v\|·v。k = dragK，与密度成反比 materials.yml 的 air-drag 与 density
    浮力 靠 gravityScale 实现 —— 中性浮力时为 0，上浮时为负 物体 density（水 1.0 / 岩浆 3.0）
    流体阻力 水 drag=2、岩浆 drag=8 引擎常量（ClusterPhysicsWorld）
    摩擦 接触约束的切向分量，走库仑模型 materials.yml 的 friction
    弹性 恢复系数，速度求解阶段生效 materials.yml 的 bounciness

    重力里没有质量🔗

    b.vy += gravity * b.gravityScale * h;

    F = mg 两边同时除以 m 就只剩 g。真空中一切物体同加速度下落。

    「羊毛飘、铁块砸」从哪来

    全部来自二次空气阻力：dragK 与密度成反比，于是终速 v = √(g/k) 对轻材质低得多。

    这是从物理量里长出来的，不需要任何特判 —— 也意味着调重力不会改变轻重差别， 要改的是 materials.yml 的 density 与 air-drag。

    摩擦决定的是「废墟能堆多陡」🔗

    碎石堆的休止角 θ 满足 tan θ = μ，而 μ = 0.75 × friction：

    friction μ 休止角 参照
    0.05 0.04 2° 冰，堆不起来，全摊平
    1.0 0.75 37° 默认。真实碎砖 / 碎混凝土是 35°~45°
    1.2 0.90 42° 沙砾
    2.0 1.50 56° 蜂蜜块，几乎垂直堆着不倒

    「塌成一堆是什么形状」是玩家判断塌得像不像的主要依据，比任何单块碎石的运动都显眼。

    线性 / 角阻尼🔗

    linearDamping / angularDamping 与空气阻力是两回事：它们压掉的是数值残余， 量级远小于空气阻力。默认 angularDamping = 0.05。

    B 类：场力🔗

    力 语义 入口
    引力井 向心吸引，a = strength/(r²+1)，近到吞噬半径即销毁 api.gravityFields().createField(...)
    磁力场 同为径向场，但可吸引（正）也可排斥（负），不吞噬 api.magnetics().createField(...)

    两者的共性是「以某点为中心的径向场」，引擎内部走同一个施力通道 —— 物理线程每子步对半径内刚体叠加场力，「是否吞噬」「是否分极性」由场类型决定。

    记账时都归 ForceGroup.FIELD。

    C 类：瞬时力🔗

    力 语义 入口
    冲量 一次改变线速度，Δv = J/m PhysicsBody.applyImpulse(x, y, z)
    力偶矩 一次改变角速度 PhysicsBody.applyTorque(x, y, z)
    爆炸冲击 以点为中心的径向冲量 + 向上偏置，随距离线性衰减 PhysicsBodyService.applyExplosion(center, radius, power)
    水面反弹 刚入水且垂直速度够大时反弹垂直速度（打水漂） 浮力系统内部

    C 类都是「调用即施加、下一帧不再有」。

    连续效果（载具油门、直升机升力）由调用方每 tick 重复施加来表达 —— examples/vehicle-addon 的七种操控律就是这么写的。

    为什么攻击配的是速度而不是冲量

    collision.yml 的 interact.attack-speed 配的是「一次攻击给单个方块带来的速度增量」。

    配冲量的话，服主得先知道「一格石头有多重」（2500 kg）才填得出合理值。 而按单块质量折算之后，打一整面 64 格的墙只能获得 4/64 ≈ 0.06 m/s —— 这正是应该的（墙比一块砖重 64 倍），且不需要任何特判，是 Δv = J/m 自己给出来的。

    D 类：约束力🔗

    力 实现
    法向支撑 接触约束的位置投影（POSITION_ITERATIONS = 4）
    堆叠传递 同上，多层堆叠靠子步数而非迭代数稳住
    库仑摩擦 速度求解阶段（VELOCITY_ITERATIONS = 8）
    铰链 / 滑轨 / 球铰 / 摆动扭转 Constraints 的四种类型，顺序求解

    D 类没有独立的「施力 API」—— 它是求解器为满足几何条件算出来的位置修正。

    引擎能配置的只有材质（摩擦 / 弹性，即 A 类）与求解器常量（写死，见引擎总览）。

    详见 XPBD 求解器 与 约束系统。

    线程归属🔗

    类别 生效线程 谁创建 / 销毁 生命周期
    A 介质 / 材料力 物理线程 材质表（主线程加载） 常驻
    B 场力 物理线程施力，主线程增删 玩法（API） 场存活期间
    C 瞬时力 主线程调用 → 排队到物理线程步进边界 玩法 一瞬
    D 约束力 物理线程 求解器自动 接触 / 约束存在期间

    共同铁律

    物理线程只读数据（材质表、场列表），主线程负责增删与调参。

    这就是为什么所有场都是「主线程创建、物理线程施力」， 以及为什么施力要走命令队列排到步进边界 —— 见 线程与数据流。

    现状清单🔗

    力 类别 状态
    引力井 B 已实现 GravityFieldService
    磁力场 B 已实现 MagneticFieldService
    悬挂 A / D 已实现。走力（ForceGroup.SUSPENSION）而非约束，见 载具
    铰链 / 滑轨 / 球铰 / 摆动扭转 D 已实现 Constraints
    风力 B 未实现。需要「恒定方向的体积力」这一新形态
    离心力 — 无需实现，是向心力的自然副产品

# 布娃娃

> 源码：`paper/object/PhysicsRagdoll.java`、`engine/Constraints.SwingTwist`

一组由关节约束连接的身体部件刚体，受重力自然倒地 ——「NPC 死亡倒地动画」的物理底座。

---

## 引擎里没有「布娃娃」这个概念

!!! important "这是刻意的"
    布娃娃就是**七个刚体 + 六条摆动扭转约束**，没有任何一样东西是它专有的。

    通用引擎（Jolt 的 `RagdollSettings`、`Skeleton`、`SkeletonPose`）为它封装了一整套骨骼系统，
    代价是关节参数、部件质量、休眠判据全藏在封装后面 —— 想调一个肩关节的锥角，
    得先搞清楚三个类之间的关系。

    少一层封装，换来的是**全都看得见、改得动**。

## 六条关节

全部是**摆动扭转约束**（`Constraints.SwingTwist`）：一个球铰 + 一个圆锥限位。

```
HIP   ──► SPINE      锚点 (0, 0.10, 0)  ↔ (0, −0.25, 0)
SPINE ──► HEAD       锚点 (0, 0.25, 0)  ↔ (0, −0.15, 0)
SPINE ──► LEFT_ARM   锚点 (−0.12, 0.20, 0) ↔ (0.13, 0.20, 0)
SPINE ──► RIGHT_ARM  锚点 (0.12, 0.20, 0)  ↔ (−0.13, 0.20, 0)
HIP   ──► LEFT_LEG   锚点 (−0.08, −0.10, 0) ↔ (0, 0.15, 0)
HIP   ──► RIGHT_LEG  锚点 (0.08, −0.10, 0)  ↔ (0, 0.15, 0)
```

锚点都**相对各自质心**。扭转轴取 Y（部件的长轴）—— 手臂绕自己的长轴扭，锥限位管的是它能甩多开。

### 锥角

```java
private static final double JOINT_CONE = Math.toRadians(60);
```

!!! tip "60 度是人体关节的量级"
    再大布娃娃就会软得像布袋 —— 四肢能反折到不可能的角度，一眼假。
    再小就变成木偶，倒地时四肢僵直。

### 为什么锥内完全自由是关键

`SwingTwist` 只在**超出锥角时**才施加修正，锥内一点干扰都没有。

这正是布娃娃「像人而不像木偶」的分水岭。木偶感来自关节被持续修正 ——
哪怕修正量很小，运动也会显得有阻滞、有黏性。

## 材质

```java
new PhysicsMaterial(density = 1.0, friction = 1.6, bounciness = 0.0, airDrag = 1.0)
```

摩擦给得比默认高：**尸体应该落地就停住**，而不是在地上滑出去一段。
弹性为 0 —— 人不是皮球。

## 锚点必须对应同一世界点

这是搭关节时最容易出错的地方，值得单独记一笔：

```
父部件位置 + 父侧锚点  ==  子部件位置 + 子侧锚点
```

!!! danger "不满足会怎样"
    初始误差极大，求解器第一帧就要把两个锚点强行拉到一起 ——
    位置修正被 1/h 放大成速度，布娃娃**当场炸开**（部件四散穿地）。

    上面那张表里的每一组数字都满足这个等式，改的时候要连着改两侧。

## 线程

在**物理线程**创建（部件刚体 + 约束，与刚体增删同线程约束）。
位姿由物理线程读，主线程广播。

七个部件的位姿存在七组 `double[]` / `float[]` 里，与 [`PoseSnapshot`](threading.md#posesnapshot) 是同一套思路。

---

## 碰撞分组

部件注册在**动态组**（`MOVING_LAYER = 1`，首个世界的 moving 组）。

于是布娃娃会与地形、其它物体、碎块正常碰撞。分组机制见 [地形 · 世界隔离](terrain.md#世界隔离)。

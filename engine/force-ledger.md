# 力记账

> 源码：`engine/ForceGroup.java`、`engine/ForceLedger.java`

每一份力在**施加的那一刻**就带上来源标签，于是事后能回答「此刻升力多大、阻力多大、谁把谁抵消了」。

---

## 它解决的是标定，不是计算

!!! important "分组对求解器没有任何影响"
    所有组的力最后都加进同一个总和。记账存在的唯一理由是**可观测性**。

### 病象

一台直升机飞不起来。可能是：

- 推力不够
- 阻力算大了
- 悬挂在偷偷吃掉升力
- 控制律的姿态修正量把升力抵消了

**力一旦进了刚体就只剩一个合力向量，事后没有任何办法把它拆回去。**

于是调参只能靠猜：改一个系数跑一次，十几个系数互相纠缠。
这正是载具参数长期停在「待标定」状态的根源 —— 不是没人调，是**调了看不见效果归因**。

### 治法

在 `RigidBody` 累加力时顺手记一笔来源。调试面板于是能把合力拆回九项明细。

---

## 九个来源

| 组 | 含义 |
|---|---|
| `PROPULSION` | 引擎推力、螺旋桨、火箭 —— 一切「主动往前推」的力 |
| `LIFT` | 旋翼升力、机翼升力、反重力托举。与 `BUOYANCY` 的区别是**它需要耗能** |
| `DRAG` | 空气与水的阻力，含控制律里的软限速 |
| `SUSPENSION` | 悬挂弹簧与阻尼给出的支撑力 |
| `TIRE` | 轮胎的纵向（驱动 / 刹车）与侧向（抓地）力 |
| `BUOYANCY` | 浮力。不耗能，由排开介质的体积决定 |
| `CONTROL` | 姿态稳定、速度收敛这类控制器修正量。**它常常是「手感」问题的真凶** |
| `FIELD` | 场力：重力井、磁力场、风场。按位置分布，不属于任何一台载具 |
| `EXTERNAL` | 插件与 addon 通过公开 API 施加的力，来源不在引擎内部 |

### 为什么是枚举而不是可注册的表

参考实现（VVE 3.0）用的是可由数据包扩展的注册表。这里不需要 ——
**力的来源由控制律的代码决定，不由配置决定**，能出现的组在编译期就是封闭的。

枚举换来的是 `ordinal()` 直接当数组下标，热路径上没有一次哈希查找。

---

## 默认不存在

账本**只在明确开启时才分配**。

碎块可能同时有上千个，给每个都挂一份 `9 组 × 6 个 double` 的明细纯属浪费 ——
而真正需要看明细的，永远只是玩家正在调的那一台载具。

```java
if (body.ledger() != null) { ... }   // 为 null 时，记账路径上一条指令都不会执行
```

## 跨线程读取

写在**物理线程**，读在**主线程**（调试面板、命令）。

这里不加锁，而是每帧提交时把当前值**拷贝**成一份新数组再发布：

```
live       物理线程正在累加的这一帧
published  上一帧提交的结果，volatile，供其它线程读
```

读者拿到的引用此后永远不会被写 —— 既读不到撕裂的数据，也不必阻塞物理线程。

代价是开启记账后每帧多一次 `double[54]` 的分配。这是**调试期才付的账**，稳态零开销。

### 每组 6 个 double

```
0..2  线性力（N，世界坐标）
3..5  力矩（N·m，世界坐标）
```

## 空帧宽限

`EMPTY_FRAMES_BEFORE_CLEAR = 4`

物理跑 40 Hz 而驾驶逻辑跑 20 Hz，于是**一半的物理帧本来就没有新的力**。

照实发布成 0 的话，面板读数会以 20 Hz 闪烁，根本没法读。
留 4 帧余量再清零 —— 既不闪，也不会在松开操纵杆之后一直显示着旧数字。

!!! tip "这类细节决定一个调试工具好不好用"
    一个闪烁的数字和一个没有数字，在实用性上是一样的。

    载具 addon🔗

    源码：examples/vehicle-addon · 命令 /gtrpveh

    把「选车 → 预览 → 开出来 → 驾驶 → 随时换车」整条链跑通的完整玩法系统。 只通过 RigidPhysicsAPI 访问物理能力，不碰引擎任何内部类。

    外观来源

    盔甲架模型来自 VehiclesWASD，已获原作者授权 （见仓库根的 THIRD_PARTY_NOTICES.md）。几十上百个原版方块拼出来，不需要资源包。

    行为则是真算出来的：轮式车走引擎的射线悬挂载具，会飞会漂的由 addon 自己写控制律。

    十一种载具，五种驱动🔗

    驱动 载具 特点
    陆行 卡丁车、概念跑车、沙滩四驱、摩托车、拖拉机、坦克 真悬挂：上马路牙子会颠，漂移会甩尾
    水上 快艇、摩托艇 浮力由引擎给（密度低于水就浮），控制律管推进与「不许横着漂」
    旋翼 直升机 推力永远沿机顶，靠倾斜机身换水平移动；旋翼真的在转
    固定翼 螺旋桨飞机 唯一会失速的：速度不够抬头也没用，只能低头换速度
    悬浮 飞碟 关掉重力，指哪走哪，碟身永远水平

    玩法🔗

    操作 说明
    /gtrpveh 或 /gtrpveh garage 打开车库菜单
    菜单里左键 选中车型并立刻开一辆出来（正在开车时是原地换车）
    菜单里右键 关掉菜单，在面前悬浮一个自转的整车预览
    /gtrpveh <车型> 跳过菜单直接开出来
    /gtrpveh preview [车型] / preview stop 单独开关预览
    /gtrpveh clear 清空场上所有载具
    /gtrpveh reload 重读配置并重新装配全部车型（权限 gtrpveh.admin）
    右键载具 上车
    视角偏航 就是方向盘：看向车头前进、左右转视角转向、扭头看车尾刹车
    视角俯仰 会飞的才用得上：抬头爬升、低头下降
    Shift 下车（飞在空中时也一样，请自备鞘翅）

    可视化蓝图搭建🔗

    用方块在世界里搭一辆车，框出来、标好哪些是轮子和引擎，存成蓝图。

    操作 说明
    /gtrpveh build tools 领一套工具（权限 gtrpveh.build）。反复领不会重复，先收再发
    选区杖（金斧）左 / 右键方块 定选区的两个角，边框以粒子实时描出
    标注杖（刷子）左键 轮流切换要标注的角色
    标注杖 右键方块 标成当前角色；潜行 + 右键取消
    蓝图杖（纸）右键 在面前展开最近保存那份的预览；潜行 + 右键关掉
    蓝图杖 左键 把预览转 90°
    保存（绿宝石）右键 弹出命名窗口，填完即存。选区不消失，可接着改再存一份
    退出（屏障）右键 丢掉选区与标注、收回工具，这一版草稿不保存

    配套命令：blueprint list / save / edit / preview / drive / delete、build exit。

    八种功能件🔗

    角色 作用
    轮子 轮心与半径由这一簇方块算出。前轮自动转向、后轮自动驱动兼手刹
    引擎 每多一台，轮上峰值扭矩提高一档（收益递减）
    座位 司机的位置，也是上车时玩家被放到的地方
    油箱 配重。标在车尾重心就往后移，加速更容易翘头
    旋翼 标了它就是直升机。数量决定推重比
    机翼 标了它就是固定翼。翼展决定失速速度 —— 短翼要跑更快才拉得起来
    推进器 直接推力：船的螺旋桨、飞机的发动机。与引擎的分工是「推力 vs 扭矩」
    锚点 车身原点。不标则取包围盒底面中心

    装配是自动的🔗

    存完蓝图立刻装成一辆可驾驶的车，不需要填任何参数表：

    • 是什么车由标注组合推断 —— 旋翼 → 直升机，机翼 → 固定翼，两个以上轮子 → 轮式，只有推进器 → 船，什么都没有 → 悬浮
    • 哪些轮子转向按前后位置判
    • 质量按方块数折算，油箱额外加重
    • 推力由推重比反推，保证直升机一定飞得起来
    • 失速速度由翼载（质量 ÷ 机翼方块数）解出

    推出来的值不一定最优，但一定自洽且能开

    参数之间互相牵制 —— 推力不够就飞不起来、翼载太高就一直失速。 逐个手填几乎不可能一次填对。

    车头朝哪🔗

    保存时你面朝的方向就是车头。 蓝图按这个方向规范化存下来 —— 站在车尾看着车头按一下就行，不用记任何坐标轴口诀。

    预览里的功能件会发光，颜色按角色分（轮子绿、引擎橙、座位蓝……）， 顶上有悬浮文字写着「轮子 1/4」。连在一起的方块（面接触或棱接触）会自动算成同一个轮子， 所以四个轮子就是四盏绿光、四块标签，而不是三十块。

    蓝图存在 plugins/GTRP-Vehicle-Addon/blueprints/<名字>.yml，是人类可读的 YAML —— 方块表用调色板压过，出问题能直接打开看、能手改一个标注、能发给别人。

    蓝图与车型是同一张表：存一份蓝图等于往车库里加一辆车，删一份那辆车当场消失，不需要 reload。

    头颅皮肤单独存🔗

    自定义头颅的皮肤不在方块状态里 —— player_head[rotation=4] 只描述朝向，皮肤挂在方块实体上。

    文件 装什么
    heads/textures.yml 插件自带模型用到的那十几张，全服共用
    blueprints/textures/<蓝图id>.yml 这份蓝图用到、而上面那份没有的 —— 玩家自己带来的头颅

    分层的边界是谁带来的，不是先来后到：同一份蓝图存几次结果都一样。

    皮肤图片由客户端自己下载

    属性里存的是 textures.minecraft.net 的 URL，客户端只信任 Mojang 的域名，服务端无法代劳。 缓存能保证的是「头颅带着正确的皮肤信息发出去」；客户端连不上 Mojang 时仍然会是史蒂夫。

    它演示了 API 的哪些能力🔗

    功能 用到的 API
    拼装外观 SpawnOptions.model(BodyModel) —— 几十个 ModelPart，每个是「一件物品 + 一份局部变换」
    轮子跟着物理转 ModelPart.wheel(index) —— 绑到第 N 个物理轮子，悬挂压缩 / 转向 / 滚动由引擎算
    旋翼自转 ModelPart.spin(axis, degreesPerSecond) —— 相位由绝对时间算，所有观众看到的一致
    轮式载具 SpawnOptions.vehicleSettings(...) + PhysicsBodyType.VEHICLE
    轮式驾驶 每 tick 给 Vehicle 句柄喂油门 / 转向 / 刹车
    飞行 / 航行 applyImpulse 给推力升力、velocity() / angularVelocity() 读状态、setAngularVelocity 控姿态、setGravityFactor 让飞碟悬空
    可见性 （无需调用） 引擎按距离逐玩家自动裁决
    上车判定 bodies().activeBodies() + 距离筛选（公开 API 没有射线，玩法逻辑归 addon）
    状态清理 PhysicsBodyRemoveEvent

    模型是怎么搬过来的🔗

    VehiclesWASD 的模型是几十个不可见小盔甲架，每个戴一件方块当零件， 靠 offset 摆位、靠 pose 掰角度。本 addon 把它们换算成 ItemDisplay。

    为什么必须换

    一个 ItemDisplay 就是一个完整的仿射变换，车身翻滚、侧倾、上坡都能表达，客户端还会自己插值； 而盔甲架整体只有一个 yaw —— 一辆翻过来的车根本画不出来。

    这套载具的卖点就是真物理，车会翻，渲染必须跟得上。

    换算不是试出来的，是照着原版渲染管线推的：

    • 头盔槽走 CustomHeadLayer（头枢轴 1.4385 + 沿朝向偏 0.25 + 缩放 0.625）
    • 手持槽走 ItemInHandLayer（臂枢轴 + 一次 rotateX(-90)）

    推导写在 StandGeometry 的类注释里，几何部分单独拆成 StandTransforms 并有测试。

    车看起来整体偏了一点或大了一圈？

    改 config.yml 的 armor-stand-geometry 就行，不用等插件更新。

    最可能需要动的是 skull-scale —— 模型里的车轮全是玩家头颅，那个数直接决定轮子多大。

    已知的一处降级🔗

    摩托车模型里有 5 个零件没戴装备，而是把盔甲架自己的木质躯干与手臂当车架用。 那是实体模型不是物品模型，ItemDisplay 拿不到，只能用一块木头顶上去 （config.yml 的 stand-substitute，默认 STRIPPED_OAK_LOG）。远看差不多，近看能看出是木头。

    四种非轮式驱动怎么算🔗

    轮式车有引擎的载具控制器兜底，其余四种的动力学全在 drive/law 里。两条贯穿始终的原则：

    主控走冲量，不直接写速度🔗

    直接把速度写进刚体最省事、手感也最听话，但那等于把载具从物理世界里摘出去 —— 撞上东西不会有像样的反弹，被爆炸掀翻也纹丝不动。

    所以推力与升力都是 applyImpulse，只有「限速」「扶正」这类需要硬约束的地方才碰速度。

    姿态由驾驶员说了算🔗

    一架飞机的机头指向哪儿不该由转动惯量和空气动力学「商量」出来 —— 那样既难调也难开。 所以姿态走 setAngularVelocity 直接给。

    但只在有人驾驶时接管

    人一下车就完全交还给物理，无人机该怎么翻就怎么翻。

    两个具体选择🔗

    直升机的推力永远沿机顶，而不是「按视角方向给个水平推力」。 后者写起来简单，但那样直升机就是个会飞的方块 —— 悬停、前倾加速、回正减速这些动作全没有了。

    照真机来做之后，机身一倾推力自然分出水平分量，松手回正就自己减速； 代价是倾斜时垂直分量变小，推力要除以倾角余弦补回来 —— 那也正是真直升机大坡度转弯要拉总距的原因。

    飞机会失速：升力正比于前向速度的平方，低于失速速度按速度比的平方衰减。 速度不够时抬机头没用，只能低头换速度。这让「起飞要先滑跑」成为真的规则。

    语言🔗

    界面语言在 config.yml 的 locale 里选，内置 zh_CN 与 en_US，文件在 lang/ 下。

    想加一种语言，往 lang/ 里丢一个同结构的文件即可，不需要改代码 —— 缺失的条目会自动回退到 zh_CN，所以翻译到一半也能正常用。

    文案里的颜色写的是语义标签（<accent>、<danger>、<wheel>……）而不是颜色名。 想整体换配色，改 i18n/Messages.java 里那张色板；想给某句话单独指定颜色，直接写 <#RRGGBB> 也行。

    当前状态🔗

    编译通过，但零真机验证

    这个 addon 移植了 WASD 的全部 11 种载具与配套系统，编译零警告， StandTransformsTest 与 AttitudeTest 覆盖了坐标换算与姿态符号约定。

    但几何常量与飞行手感尚未在真机上标定。上面提到的 armor-stand-geometry、 skull-scale、推重比、失速速度这几处，很可能需要按实机表现调整。

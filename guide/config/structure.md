# `structure.yml` —— 承重结构

这份文件控制「**建筑什么时候该塌、怎么塌**」。

在它出现之前，倒塌判定只有「连着 / 没连着」两态：挖掉一根承重柱，
只要上方还靠侧墙勉强连着地基，就一动不动。
承重分析补上了第三种失效方式：**还连着，但扛不住了**。

诊断命令：`/gtrp structure info`（准星方块的载荷 / 容量 / 构件类型）、
`/gtrp structure scan`（扫描周围最吃紧的点）。

---

## 载荷的单位

全套系统用的是「**方块自重当量**」，不是牛顿：一个 `density = 1.0` 的方块贡献 1.0 载荷。

于是 `materials.yml` 里 `compressive-strength: 120` 可以直接读成
**「这块石头能扛 120 个基准方块压在头上」**。不需要懂力学也能调。

---

## 总开关

```yaml
enabled: true
```

关掉后退回旧行为：只有**完全脱离地基**的结构才会塌。
挖空承重墙但上方还连着侧墙时，楼会一动不动地悬着。

## 载荷与强度

```yaml
strength-scale: 1.0
self-weight-scale: 1.0
max-iterations: 12
span-failure: true
min-load-threshold: 0.01
support-weights:
  direct: 4.0
  edge: 1.0
  corner: 0.25
```

### `strength-scale` —— 调整倒塌手感的总旋钮

乘在每种材质的抗压强度上。比逐个改材质方便得多，而且**不会破坏材质之间的相对关系**
（石头依然比木头结实）。

| 值 | 表现 |
|---|---|
| `0.5` | 一碰就塌，场面极其夸张 |
| `1.0` | **默认**。破坏承重结构必有明显后果 |
| `2.0` | 保守，需要破坏大量承重构件才垮 |

### `self-weight-scale` 与它是一对反向旋钮

通常只需要调其中一个。两个都留着是因为**观感并不等价**：

- 调高自重 → **高层建筑先垮**（楼越高底层压力越大）
- 调低强度 → 一视同仁地脆

### `max-iterations` —— 连锁压溃

一个方块被压溃后，它原本扛着的载荷转嫁给邻居，邻居可能因此也超载 ——
这就是**连续倒塌**，真实建筑大面积垮塌的主要机制，也是「打断一根柱子，整片垮下来」的来源。

| 值 | 效果 |
|---|---|
| `1` | 关闭连锁，只塌直接超载的那一批 |
| `12` | **默认**，足以让一整片结构垮下来 |

开销不是简单相乘：第二轮起只从最高失效层往下重算，而连锁通常集中在建筑底部。

### `support-weights` —— 载荷往下怎么分

只有**相对比例**有意义，绝对值无所谓（分配时会归一化）。

默认 `4 : 1 : 0.25` 表达的是「载荷主要沿竖直方向走，斜向只分走一小部分」。

!!! danger "三者调得接近会让整套系统白装"
    载荷会像水一样向四周摊平，于是打断任何单根柱子都不会有明显后果。

### 其余两项

- `span-failure` —— 是否启用**悬挑弯折**失效。关掉后楼板能凭空伸出几十格。仅排查问题时才该关
- `min-load-threshold` —— 小于该值的载荷不再向下传递。纯粹的数值卫生（斜向分配会产生大量无限衰减的尾巴）

## 构件识别

> 「同样是石砖，这根是承重柱，那块是装饰」

只看材质回答不了这个问题，而它恰恰决定打断它会不会塌楼。

真实建筑的承载力不只来自材料，更来自**几何形状**：
同样一吨混凝土，做成柱子能扛楼，摊成一层皮谁也扛不住。

按连续跨度**自动推断**，不需要地图作者做任何标注。
判定顺序：**柱 → 梁 → 承重墙 → 楼板 → 填充**，先匹配先胜出。

### `members.grouping` —— 相邻两格算不算同一个构件

| 值 | 口径 |
|---|---|
| `SOLID` | 只要是实心方块就算连续。最宽松，代价是「石柱穿过木地板」时地板会被算进柱子的厚度 |
| `SAME_STATE` | 必须是完全相同的 blockstate。最严格，但对朝向敏感（同一根柱上朝向不同的两块楼梯会被判成断开） |
| `STRENGTH_CLASS` | **默认**。抗压强度落在同一数量级档位就算连续 —— 石砖与凿制石砖接得上，石砖与玻璃接不上 |

### 五类构件

| 构件 | 判据 | 强度系数 | 跨度系数 | 为什么 |
|---|---|---|---|---|
| **柱** `column` | 高 ≥ 3、厚 ≤ 3 | 2.5 | 1.0 | 承重骨架的主角。厚度取 3 是为了兜住塔吊、烟囱这类粗一点但仍然是杆的结构 |
| **梁** `beam` | 长 ≥ 4、厚 ≤ 3 | 1.2 | **2.5** | 跨度系数最高 —— 梁的存在意义就是「下面没有支撑也能挑过去」 |
| **承重墙** `wall` | 高 ≥ 3、长 ≥ 4 | 2.0 | 1.5 | 厚度不限，厚墙依然是墙。面积大、载荷摊薄，所以**墙上打个洞不塌，拆整面才塌** |
| **楼板** `slab` | 厚 ≤ 2、展开 ≥ 3 | **0.8** | 1.5 | 系数低于 1 是刻意的 —— 楼板是用来铺的不是用来扛的 |
| **填充** `fill` | 其余 | 1.0 | 1.0 | 家具、腰线、零散装饰，完全按材质本身走 |

实际容量 = 材质的 `compressive-strength` × 构件系数。
同样是石砖，做成柱子（×2.5）比摊成楼板（×0.8）能扛三倍多。

## 簇切分

> 塔吊要「倒下来」，不是「碎成积木掉下来」

```yaml
clusters:
  coherent-members: true
  min-member-run: 6
  max-member-cluster-size: 256
  topple-min-aspect-ratio: 2.0
  topple-angular-velocity: 0.35
```

### `coherent-members`

是否让识别出的柱 / 梁 / 桁架**整根保留成一个簇**，不按空间网格切碎。

关掉则塔吊会碎成一堆 4×4×4 的积木同时松手往下掉，
而不是绕着根部旋转、塔尖划出一道弧线扫向远处。

!!! important "这两者的观感差距比任何材质参数都大"

### `max-member-cluster-size` 是一个直接的带宽旋钮

簇在表现层是一个骑乘组：平移只要 1 个包，但**旋转要给每个方块各发一次 metadata**。

而整根构件恰恰最需要旋转 —— 它就是靠转起来才叫「倒下」。

```
256 个方块的姿态关键帧 ≈ 18 KB
按 2 Hz 发 = 36 KB/s
单个玩家的物理带宽预算 = 50 KB/s
```

超出上限的部分退回网格切分，于是超长结构表现为「主体整根倒下，末端碎裂」——
这恰好也是真实长构件的失效样子。

**服里经常同时倒好几座塔的话，把这个值往下调。**

### 其余三项

| 键 | 默认 | 说明 |
|---|---|---|
| `min-member-run` | 6 | 构件至少多长才值得整根保留。三格长的短柱没有观感收益，却白占一个旋转配额 |
| `topple-min-aspect-ratio` | 2.0 | 高宽比达到多少才判「该倒而非该掉」。调低会让敦实的结构也开始翻滚 |
| `topple-angular-velocity` | 0.35 | 倾倒的初始角速度（rad/s）。只是「推它一把」让它选定倒向，之后交给求解器。调大会像被巨力抽了一鞭子 |

## 濒危预警

> 塌之前先吱呀作响

```yaml
critical:
  enabled: true
  threshold: 0.85
  delay-ticks: 30
  particles: true
  sound: true
  max-tracked: 512
```

超载的方块不立刻垮，而是先进入「濒危」：裂纹粒子 + 结构呻吟音效，延迟一小段时间后才真正塌。

这既是听觉 / 视觉预告，也给了玩家**逃生窗口** ——
建筑无预警地瞬间消失，玩家只会觉得是 bug 而不是玩法。

| 键 | 默认 | 说明 |
|---|---|---|
| `threshold` | 0.85 | 载荷率达到多少算濒危。0.85 = 只剩 15% 余量 |
| `delay-ticks` | 30 | 从判定超载到真正垮塌的延迟。`0` 立刻塌没有预告；`30` = 1.5 秒够玩家听见声音往外跑；`100` 是夸张的慢镜头 |
| `max-tracked` | 512 | 同时跟踪的濒危方块上限。超出的新濒危方块直接跳过预警立即塌 |

!!! important "延迟只压在被压垮的那部分上"
    同一次分析里，纯粹「失去支撑」的方块（玩家一镐挖空了它下面）**不等预警，立刻就掉** ——
    它们本来就该立刻掉，陪着等 1.5 秒只会让人觉得插件卡了。

    判据是「把承重失效去掉再问一次谁没支撑」。

`max-tracked` 是护栏而非玩法参数：一次大规模爆炸可能产生上万个濒危格，
全部跟踪会让粒子与音效彻底盖住服务器。

## 连锁倒塌

> 塔吊倒下来砸坏旁边的房子，房子跟着塌

```yaml
chain:
  enabled: true
  max-depth: 3
  min-impact-blocks: 4
  delay-ticks: 10
```

| 键 | 默认 | 说明 |
|---|---|---|
| `max-depth` | 3 | 连锁最多传播几级 |
| `min-impact-blocks` | 4 | 一次撞击至少砸坏多少方块才触发下一级 |
| `delay-ticks` | 10 | 触发下一级前的延迟 |

!!! warning "级数是指数级放大开销的"
    每一级都是一次完整的结构分析。一次倒塌砸中三栋楼，每栋又砸中三栋 ——
    **三级就是 27 次分析**。

    3 是经验值，视觉上已经足够「一片片连着倒」。

`min-impact-blocks` 的意义是过滤掉「碎块蹭掉一格墙皮」这种噪音 ——
没有它，每一块落地的碎石都会触发一次全量结构分析。

`delay-ticks` 给上一级的碎块一点时间真正砸下去，也把多次撞击合并成一次分析。

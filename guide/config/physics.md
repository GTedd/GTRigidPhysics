# `physics.yml` —— 物理

四个键，但其中 `gravity` 牵一发动全身。

---

## `workers`

```yaml
workers: 2
```

物理求解的**并行度建议值**。

!!! warning "目前只是个建议值"
    岛并行尚未接线，求解仍是单线程。改它当前不会有任何效果。

    留着是因为落点已经在 `PhysicsWorkspace` 里了，接上之后这个键即刻生效。
    详见[性能与上限](../../engine/limits.md#3-求解器本身)。

不要设高 —— 物理不该与主线程 / 网络线程抢核心。

## `gravity`

```yaml
gravity: -9.81
```

重力加速度（m/s²），负值向下。

本插件的定位是「在 Minecraft 里还原物理效果」，所以重力是一个**真实的物理量**：
你设定全局 `g`，每个刚体按 `F = m·g` 受力。

| 值 | 是什么 |
|---|---|
| `-9.81` | **默认**。地球 |
| `-1.62` | 月球。坍塌会慢得多、飘得多，很有辨识度 |
| `-16` | 与原版落沙一致。原版 `FallingBlock` 是 0.04 格/tick² = 16 m/s²，**比地球重力还重 63%** |
| `0` | 失重 |

选 `-16` 的收益：被震落的原版沙砾会与物理碎块**严丝合缝地同步下落**。
选地球重力，碎块会比原版沙砾慢一点（落 3 格差约 0.17 秒）。

### 质量的差别不来自重力

真空中一切物体同加速度下落 —— 重力项里没有质量。

想要「羊毛飘、铁块砸」，调的是 [`materials.yml`](materials.md) 的 `density` 与 `air-drag`
（空气阻力与密度成反比）。

!!! danger "改这个值等于改了整套速度量纲"
    `materials.yml` 的 `fracture-speed` 与 `impact.yml` 的 `min-break-speed`
    都是「落 N 格的着地速度」，换算式 `v = √(2gh)` 里的 `g` 就是这里。

    改成 `-16` 却不改那两处，表现是「什么都一摔就碎」—— 那两处要跟着乘 **1.28**。

运行时可用 `/gtrp sim gravity` 临时覆盖；本项是重启 / 重载后的初值。

## `max-bodies`

```yaml
max-bodies: 4096
```

独立物体共享物理世界的**刚体总数上限**。

这个数必须同时装下四类东西，它们抢的是同一个池子：

| 用途 | 额度 |
|---|---|
| 独立物体（骰子 / 载具 / 机关 / 多米诺） | 最多 256 |
| 布娃娃部件 | 最多 32 具 × 7 = 224 |
| 虚拟角色的 inner body | 最多 64 |
| **地形流送的格子碰撞体** | 剩下的全归它 |

前三类合计 **544 是固定预留**，超出部分才是地形可用的额度。

!!! example "这个数曾经写死成 1024"
    扣掉预留只剩 480，十几个分散的物体就能耗尽。
    之后建不出新刚体，表现为**物体脚下突然没有地面、直接穿下去**。

    4096 给地形留了约 3500 格的额度，够几十个物体各自带一片地形。
    内存代价很小（刚体表按上限预分配，约每刚体几十字节）。

地形按 8×8×8 一格建一个刚体，每个物体身边要 3×3×4 = 36 格。

## `max-simulation-seconds`

```yaml
max-simulation-seconds: 15
```

单场坍塌的最长模拟时间（秒）。

**正常结束条件是所有碎块休眠**，这个值只是防泄漏的兜底。

触发时还在运动的碎块会被强行定格并就地写回方块，表现为悬空方块。

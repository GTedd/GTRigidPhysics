# `materials.yml` —— 方块物理材质

覆盖 Minecraft 26.2 的**全部 1113 个可破坏方块**，按真实材质大类分组。

完整的系统说明在[物理材质](../../features/materials.md)，这一页是配置参考。

---

## 「全部」这两个字是有测试守着的

`MaterialCoverageTest` 拿官方 `server.jar` 里的方块清单逐个跑一遍查找，
**只要有一个方块落到 `defaults` 就让构建失败**。

!!! example "这道闸门是有来历的"
    2026-08-22 的一次审计发现：**284 个方块（25.5%）静默地吃着默认值**，
    其中包括圆石、砂岩、砖块、花岗岩、陶瓦这些最主力的建材。

    配置文件表面上写得满满当当，看不出任何异常。

改过本文件之后跑一次 `/gtrp material audit` 仍然是好习惯。

## 八个字段

### 前五项决定「塌下来之后怎么运动」

| 字段 | 单位 / 范围 | 说明 |
|---|---|---|
| `density` | 相对值，`[0.001, 1000]` | 密度倍数。1.0 = 基准质量 ≈ 1000 kg/m³ 每方块 |
| `friction` | `[0, 2048]` | 摩擦修正系数。1.0 = 普通粗糙表面 |
| `bounciness` | `[0, 1]` | 弹性 / 恢复系数。0 = 完全不弹，0.85 = 史莱姆 |
| `air-drag` | `[0, 2048]` | 空气阻力修正。> 1.0 更飘（羊毛、树叶），0 = 真空 |
| `fracture-speed` | m/s | 落地破碎阈值。不填 = **永不破碎** |

### 后三项决定「会不会塌」

服务于[承重分析](structure.md)，与上面五项**互不干涉**。

| 字段 | 默认 | 说明 |
|---|---|---|
| `compressive-strength` | 64 | 抗压强度，单位是**方块自重当量**。120 读作「能扛 120 个基准方块压在头上」 |
| `span-limit` | 3 | 悬挑跨度上限（格）。0 = 完全不能悬挑，下方一掏空立刻掉 |
| `load-bearing` | `true` | `false` 表示「载荷到我为止」 |

默认 `compressive-strength: 64` **刻意偏低** —— 本插件的取向是让建筑塌得动。

实际容量还要乘**构件系数**：同样是石砖，做成柱子（×2.5）比摊成楼板（×0.8）能扛三倍多。

!!! tip "`load-bearing: false` 是「打碎玻璃幕墙不该让楼塌」的落点"
    它照常撑得住自己、照常接收压在头上的重量（因而也会被压垮），
    但**不再把载荷继续传下去或横向传出去**。

    楼的载荷路径从一开始就绕开了幕墙。玻璃、地毯、树叶属于这一类。

## `friction` 真正决定的是废墟能堆多陡

碎石堆的休止角 θ 满足 `tan θ = μ`，而 `μ = 0.75 × friction`：

| `friction` | μ | 休止角 | 参照 |
|---|---|---|---|
| 0.05 | 0.04 | 2° | 冰，堆不起来，全摊平 |
| 1.0 | 0.75 | 37° | **默认**。真实碎砖 / 碎混凝土是 35°~45° |
| 1.2 | 0.90 | 42° | 沙砾 |
| 2.0 | 1.50 | 56° | 蜂蜜块，几乎垂直堆着不倒 |

「塌成一堆是什么形状」是玩家判断塌得像不像的主要依据，比任何单块碎石的运动都显眼 ——
**调这一项时想的应该是那个锥有多陡。**

## `fracture-speed` 与重力绑定

碎块在整个下落过程中达到过的**最大速度**超过它，落地时就不再原样写回，
而是走原版破坏流程：按方块自己的掉落表掉东西、播破碎粒子与音效。

树叶从高处摔下来该没了，石头不该。

自由落体 `h` 格后的速度约 `√(2gh)`，`g` 取 [`physics.yml`](physics.md) 的 `gravity`（默认 9.81）：

| 落差 | 速度 |
|---|---|
| 1 格 | ≈ 4.4 |
| 3 格 | ≈ 7.7 |
| 5 格 | ≈ 9.9 |
| 10 格 | ≈ 14.0 |
| 20 格 | ≈ 19.8 |
| 30 格 | ≈ 24.3 |

刚体速度上限是 39.2 m/s（原版落体终速），所以填 999 也等于永不碎。

!!! danger "改重力必须连带改本表"
    把重力改成原版尺度的 `-16` 之后，同样的落差有 **1.28 倍**的着地速度 ——
    下面所有 `fracture-speed` 都要乘 1.28，否则「什么都一摔就碎」。

破碎只在该方块的落地模式是 `RESTORE` 时才判定。
区域规则已经是 `DROP` 或 `VANISH` 的，说明服主本来就不想让废墟留下来，再叠一层破碎没有意义。

## 三层查找

```
精确方块名（blocks）> 名称后缀组（groups，取最长匹配）> 默认值（defaults）
```

每层都是**部分覆盖** —— 只写想改的字段，其余继承上一层。

```yaml
defaults:
  density: 1.0
  friction: 1.0
  bounciness: 0.0
  air-drag: 1.0

suffixes:
  _WOOL:
    density: 0.25
    air-drag: 2.5
  _LEAVES:
    density: 0.1
    air-drag: 4.0
  _CONCRETE_POWDER:
    density: 1.6
    friction: 1.3

blocks:
  ICE:
    friction: 0.05
  SLIME_BLOCK:
    bounciness: 0.85
    friction: 1.6
    density: 0.4
```

### 后缀组省的不是一点点

原版有 16 种羊毛、11 种原木。没有这一层，把羊毛调轻要写 16 行。

**取最长匹配**保证 `_CONCRETE_POWDER` 正确地优先于 `_POWDER`。

## 不要照抄原版硫磺方块原型

26.2 给硫磺方块加了 12 组原型，每组带一套 Mojang 调好的弹性 / 摩擦 / 空气阻力。

本表的字段名与语义正是照着同版新增的三个原版属性对齐的
（`bounciness ↔ BOUNCINESS`、`friction ↔ FRICTION_MODIFIER`、`air-drag ↔ AIR_DRAG_MODIFIER`，
连取值上限 2048 都一样）。

**但不要直接把那 12 组数值抄进来**，两个各自独立的理由：

### 1. `air-drag` 的量纲根本不同

本引擎用的是二次阻力 `a = −k·|v|·v`，其中 `k = 0.0064 × air-drag ÷ density`；
原版那三个属性乘的是逐 tick 的**线性衰减**。

原型里常见的 `0.01` 抄过来会得到终速 `√(9.81/0.000064) ≈ 391 m/s` ——
直接顶到速度上限，等于完全没有空气阻力。

### 2. 那 12 组描述的是「球」，不是「方块」

木头原型 0.9 的弹性说的是**橡胶球**，石头原型 0.6 说的是**石头球**。

照抄会让废墟堆像一地皮球一样弹跳；而 `friction` 抄成 0.3（原型的常见值）
会让碎石在地上滑开、堆不成锥 —— 休止角 `tan θ = μ` 直接被破坏。

!!! success "真正对齐了的只有一处"
    蜂巢块的 `friction = 2.0`。它是原版 sticky 原型**唯一**的成员，
    而那一格恰好就是「一块蜂巢」而非「一颗蜂巢球」，两边说的是同一件事。

原型表另一个能直接用的地方是**分类**而不是数值：它把 334 个方块分成 12 类，
可以拿来对照本表有没有把某类材料的手感排错序。

# XPBD 求解器

> 源码：`physics/src/main/java/cn/gtedd/rigidphysics/physics/engine/XpbdSolver.java`

XPBD（Extended Position Based Dynamics，扩展位置基动力学）把约束**直接投影到位置上**，再从位置的变化**反推**速度。
这与顺序冲量法（Box2D、Bullet、Jolt 走的路）是两条不同的路线，本页解释为什么这里选了它，以及为此付出了什么。

---

## 与冲量法的根本分歧

冲量法的循环是「算速度 → 解速度约束 → 积分出位置」。位置是速度的结果。

XPBD 反过来：

```
积分出一个"如果没有约束会到哪"的候选位置
        ↓
把约束投影掉，直接改位置（物体不再互相嵌入）
        ↓
v = (x − x_prev) / h        ← 速度是位置差算出来的
        ↓
在这个速度上再解弹性与摩擦
```

**速度不是被积分出来的，而是被反推出来的。** 这一句是理解后面所有设计的钥匙 ——
包括那些看起来很奇怪的防爆常量，它们全部都在处理「位置修正被 1/h 放大成速度」这一个后果。

### 为什么坍塌适合位置法

顺序冲量在两种情形下需要很多次迭代才收敛：

- **大质量比** —— 一块石头（density 2.7）压着一片玻璃（density 0.4）
- **深堆叠** —— 废墟能堆七八层，最底下那块要同时承受上面所有层传下来的约束

坍塌**同时**踩中这两条，而且是常态而非边缘情况。
位置法在这里的优势是：把预算花在**更小的时间步**上，比花在同一时间步的更多次迭代上划算得多。
这就是 `SUB_STEPS = 8` 的由来 —— 每个外层步（1/40 秒）切成 8 份，积分实际跑在 320 Hz。

## 一个子步的五道工序

### ① 积分

半隐式欧拉。先存下 `prev` 位姿（后面反推速度要用），然后：

```java
// 重力：F = mg 两边除以 m 就只剩 g
b.vy += gravity * b.gravityScale * h;

// 二次空气阻力：a = −k|v|v，k 与密度成反比
if (b.dragK > 0.0) {
    double decel = b.dragK * speed * h;
    ...
}
```

!!! note "「羊毛飘、铁块砸」是算出来的，不是配出来的"
    真空中一切物体同加速度下落 —— 重力项里没有质量。
    轻重的差别全部来自**二次空气阻力**：`dragK` 与密度成反比，于是羊毛的终速远低于铁块。
    想调这个差别，改的是 `materials.yml` 的 `density` 与 `air-drag`，不是 `physics.yml` 的 `gravity`。

### ② 生成接触

见 [接触生成](contacts.md)。每个子步都**重新生成**接触，而不是复用上一子步的 ——
位置在子步之间已经变了，旧接触手里的几何信息立刻过期。

### ③ 位置求解（×4）

把接触与约束投影掉。这一步走**雅可比 + 按接触数平均**，不走顺序（Gauss-Seidel）。
理由值得单独一节，见下方[「为什么必须雅可比平均」](#为什么必须雅可比平均)。

### ④ 速度反推

```
v = (x − x_prev) / h
ω 由姿态差的四元数取虚部
```

### ⑤ 速度求解（×8）

恢复系数（弹性）与库仑摩擦，作用在刚反推出来的速度上。同样走雅可比平均。

---

## 为什么必须雅可比平均

这是整个求解器最重要、也最反直觉的一处设计。

### 病象

一个方块**直直落下**、平拍到地面上，然后**自己转起来，边转边滑出去一格多**。冲击速度越大转得越猛。

### 病因

方块平拍落地时，底面有九个接触点，它们本该同时、对称地把刚体顶起来。
顺序求解让第一个点先在自己那个角上把刚体撬起来 —— 而角上的力臂产生的是**力矩**：

```
单个角接触的广义逆质量  w = 1/m + |r × n|² / I

对边长 1 的立方体，转动项是平移项的三倍
—— 也就是说，一次角上的位置修正，四分之三变成了旋转
```

后面的点会反向纠正一部分，但两三次迭代根本收敛不完。
残留的姿态误差再被第 ④ 步除以子步长 `h` 放大：

!!! danger "0.5° 的残留 = 2.8 rad/s 的角速度"
    这就是位置法的阿喀琉斯之踵。速度是位置差除以 `h` 得来的，而 `h` 是 1/320 秒 ——
    任何位置层面的求解残差都会被放大 320 倍变成速度。

交替正反扫描能减轻方向偏置，却治不了这个 —— 因为第一次迭代就已经把绝大部分修正做完了。

### 治法

所有接触**基于同一个状态**算出各自的修正，累加之后除以该刚体的接触数，再一次性施加。

于是对称的接触布局产生的力矩**精确抵消** —— 不是「近似抵消」，是浮点意义上的逐项相消。

代价是单次迭代收敛慢一些，用迭代次数补回来：

| 常量 | 值 | 为什么是这个数 |
|---|---|---|
| `POSITION_ITERATIONS` | **4** | 从 2 提上来的。雅可比单次收敛不如顺序法，靠次数补 |
| `VELOCITY_ITERATIONS` | **8** | 雅可比单次是**欠松弛**的：九个接触各自算出「把刚体刹住要多大冲量」，取平均后每个只贡献九分之一，而各自的广义逆质量里还有转动那一份 —— 净效果单次只完成约四分之一。少了迭代，史莱姆方块落地几乎不弹 |

!!! warning "速度求解那边同样会把方块转起来"
    位置求解对称了不等于问题解决。速度求解顺序施加冲量时，先处理的接触会先改变速度，
    后处理的面对的已是新速度 —— 第一个角点施加了远超其份额的法向冲量，带着力臂直接变成角速度。
    实测这才是「一触地就自转」的**主因**。所以两处都必须雅可比。

## 那几个防爆常量

位置法最容易出的事故是：**密堆的物体互相推挤，攒出巨大的位置修正，反推成速度之后整堆炸开**。

三道闸门拦住它：

| 常量 | 值 | 拦什么 |
|---|---|---|
| `MAX_DEPENETRATION_PER_SUBSTEP` | 0.05 格 | 单个子步最多把物体推开这么远 |
| `MAX_DEPENETRATION_SPEED` | 1.5 m/s | 由**去穿透**贡献的速度上限 |
| `MAX_DEPENETRATION_SPIN` | 2.0 rad/s | 同上，作用在旋转上 |

!!! tip "关键：它们只夹去穿透那一部分，不动真实动量"
    一块从三十格摔下来的石头该有多快还是多快。
    被夹住的只是「为了把两个互相嵌入的物体推开」而产生的那部分速度 —— 那部分本来就是数值产物，不是物理。

    `MAX_DEPENETRATION_SPIN` 同理：真实的翻倒是重力力矩在几十个子步里慢慢积累出来的，单步增量很小；
    而求解残差被 1/h 放大出来的假旋转是**单步突现**的。这道闸门只拦后者。

## 三道数值卫生阈值

这三条不防爆，防的是「永远静不下来」。

### `ANGULAR_NOISE_EPS = 0.0025 rad/s`

角速度低于它直接归零。

不加这一条，静止在地上的碎块会因为浮点残差**极慢地自转** —— 单帧看不出来，几秒之后整片废墟就都歪了，
而且永远达不到休眠阈值，于是永远在消耗 CPU 与带宽。

### `RESTITUTION_THRESHOLD = 0.5 m/s`

低于这个接近速度就不谈弹性。

取自 Box2D `b2_velocityThreshold` 的思想：静止在地上的物体每帧都有一丁点残余接近速度，
照着它算恢复系数就会永远轻微弹跳、永不休眠。

### `STATIC_FRICTION_SLIP_LIMIT = 1.0 m/s`

位置层面的静摩擦只在滑移速度低于这个值时生效。

静摩擦与动摩擦是两种不同的物理：前者「粘住不动」，后者「以 μN 的力持续制动」。

位置层面的粘住对**静置**的废墟是对的（少了它，整片废墟会因求解残差缓慢摊开）；
但把它用在**正在高速滑行**的方块上就错了：接触点被反复拽回原处，方块转而开始**翻滚**，
而翻滚的方块滚得比滑的更远。

!!! example "实测过的反直觉结果"
    没有这道门时，出现了「蜂蜜块上比石头上滑得还远」。
    加上之后，高速滑行只走速度层面的库仑摩擦，制动加速度回到 μg，材质之间的相对关系（冰 > 石 > 蜜）才真正成立。

## 休眠

由 `EngineWorld` 负责，不在求解器里：

| 常量 | 值 |
|---|---|
| `SLEEP_LINEAR_SPEED` | 0.08 m/s |
| `SLEEP_ANGULAR_SPEED` | 0.15 rad/s |
| `SLEEP_STEPS` | 连续 10 步都低于阈值才睡 |

唤醒由 `RigidBody` 判定，用的是**加速度**而非速度阈值（`WAKE_ACCEL_EPSILON = 0.8`、
`WAKE_ANGULAR_ACCEL_EPSILON = 1.5`）—— 睡着的物体速度本来就是零，拿速度判永远醒不过来。

休眠对坍塌尤其重要：一场坍塌的正常结束条件就是**所有碎块休眠**，
`physics.yml` 的 `max-simulation-seconds: 15` 只是防泄漏的兜底。

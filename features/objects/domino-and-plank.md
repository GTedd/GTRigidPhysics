# 多米诺与木板

三个「连锁物理」模板。它们存在的意义是演示**接触传递**：一块推倒下一块，动能一路传下去。

!!! info "生成入口的现状"
    见[物体模板总览](index.md)顶部的说明。

---

## 参数表

| id | 名称 | 半长 (x, y, z) | 质量 | 外观方块 |
|---|---|---|---|---|
| `domino` | 多米诺骨牌 | 1.0 × 0.1 × 2.0 | 50 | `QUARTZ_BLOCK` |
| `plank` | 木板 | 1.0 × 0.1 × 2.0 | 1 | `OAK_SLAB` |
| `slime_block` | 史莱姆方块 | 1.0 × 1.0 × 1.0 | 17 | `SLIME_BLOCK` |

骨牌与木板的**几何完全相同**，差别只在质量：50 对 1。

!!! question "同样形状为什么要两个模板"
    质量差 50 倍带来的是**完全不同的行为**：

    - 骨牌重，倒下时动能足以推倒下一块，连锁能一路传完
    - 木板轻，堆叠起来碰一下就散，适合演示「堆叠稳定性」

    这正是「质量差别通过碰撞表现出来」的直观例子 —— 两者在自由落体阶段是**一样快**的。

## 连锁效应是涌现的，不是脚本

多米诺连锁在引擎里没有任何专门代码：

```
第 1 块被推 → 绕底边翻倒（杠杆臂来自逐点接触）
        ↓ 接触
第 2 块获得法向冲量 → 越过临界角 → 翻倒
        ↓
…
```

三件事让它成立，缺一不可：

| 要素 | 来自 |
|---|---|
| **杠杆臂** | 窄相位走「点云 vs 盒」而非最小平移向量，每个接触点都有到质心的力臂 |
| **正确的惯量** | 薄板绕长轴与绕短轴差一个数量级，球形近似会让骨牌乱滚 |
| **接触冲量传递** | XPBD 的位置投影 + 速度求解 |

详见[接触生成](../../engine/contacts.md)与[质量与惯性张量](../../engine/mass.md)。

## 薄板的数值特点

半长 0.1 的薄板是求解器比较吃力的形状：

- **薄** —— 高速下容易穿透。靠[投机接触](../../engine/contacts.md#投机接触)拦住，而不是连续碰撞扫掠
- **细长** —— 惯性张量三个轴差距大，惯性积不能省
- **易堆叠** —— 一摞木板是典型的深堆叠，靠 8 个子步稳住

采样点方面，一块 1.0 × 0.1 × 2.0 的板经过[贪心合盒](../../engine/shape.md#贪心合盒)后是一个盒、26 个采样点。

## 史莱姆方块：弹性演示

`slime_block` 的外观方块决定它从 `materials.yml` 拿到 `bounciness: 0.85`。

!!! warning "实测回弹低于标称值"
    配置 0.8 时实测有效恢复系数约 **0.63**，源于雅可比平均是欠松弛的。

    史莱姆明显会弹（回弹约 2.5 格），但比标称值偏低。
    把 `VELOCITY_ITERATIONS` 从 8 提到 16 能逼近 0.75，代价是 CPU。

    详见[性能与上限 · 恢复系数收敛不足](../../engine/limits.md#恢复系数收敛不足)。

调弹性改的是 `materials.yml` 里 `SLIME_BLOCK` 的 `bounciness`，不是模板参数。

## 用 API 复现

```java
// 摆一排骨牌
for (int i = 0; i < 20; i++) {
    Location at = start.clone().add(0, 0, i * 0.6);
    PhysicsBody d = api.bodies().spawn(
            SpawnOptions.builder(at, Material.QUARTZ_BLOCK)
                    .halfExtents(1.0, 0.1, 2.0)
                    .mass(50)
                    .build());
    if (d != null) d.broadcastTo(at.getWorld());
}
```

推倒第一块用 `applyImpulse`，或者直接走过去撞它 ——
玩家是运动学刚体，会把动态刚体推开，见[虚拟角色](../../engine/character.md#它同时是能推动物理方块的落点)。
